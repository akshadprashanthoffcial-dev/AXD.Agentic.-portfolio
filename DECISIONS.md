# axd.labs — Decision Log

A running log of the important build decisions for the agent-style portfolio.
Concise on purpose — only decisions that would surprise someone new. **Add a
short entry with each new feature or prompt.**

---

## 1. Concept

- **The portfolio is an agent.** Recruiters "talk" to it: a character greets them, a search bar answers questions and routes to the right page, suggestion chips guide exploration.
- **The character is `axd.blob`** — one component reused everywhere (`components/blob/AxdBlob.tsx`). Referred to by name across the codebase.
- **Voice:** plain, friendly English (no clinical/"cleanroom" lexicon). Recruiters are the primary audience.

## 2. Stack *(locked)*

- **Framework:** Next.js 16 (App Router), React 19, TypeScript. Async dynamic `params` (`Promise<…>`).
- **Styling:** Tailwind v4, PostCSS-only, no config file. Tokens live in `app/globals.css` (`@theme` + CSS vars).
- **Motion:** dependency-free — hand-rolled `requestAnimationFrame` + CSS keyframes. **No** framer-motion / gsap.
- **Port:** `3006`. This is a **new** app; the older `axd-labs-site/` is untouched.

## 3. Visual system *(from Figma "AXD New Portfolio")*

- **Canvas:** pure black `#000`. Text tiers white / 70% / 45%.
- **Brand gradient:** `#F59B00 → #A11FF2 (49%) → #EF3C3F`. Used for the blob, borders, chip fills, glows, painted text (`.text-brand`).
- **Type:** display = **Neue Montreal** (self-hosted from `app/fonts/*.otf` via `next/font/local`), body = **Inter** (`next/font/google`).
- **Signature components:** gradient-bordered pill search bar with a blur glow; `rounded-full` sparkle suggestion chips over `--brand-sheen`.

## 4. axd.blob behavior

- Layers move **independently**: glow (breathe + proximity reaction), body (brand gradient + rotating conic sheen, tilts toward cursor), internal highlights (drift, `plus-lighter`), eyes (two white bars).
- **Eyes** track the pointer with damped lerp, **blink** on a random interval, and **look around** autonomously when the pointer is idle (>2.5s).
- One shared rAF loop; `prefers-reduced-motion` collapses to a gentle blink only.
- Props: `size`, `mode: hero | nav | footer`, `interactive`.

## 5. Search / routing *(client-side, no LLM)*

- `lib/search.ts` is a small intent index over real content (projects + about + contact).
- Live suggestions in the dropdown as you type; Enter routes to the top match.
- **No confident match → `/oops`** fun page (echoes the query, offers real chips).
- Nav on non-home pages = minimized blob pill → opens the expanded search overlay.

## 6. Content

- **5 projects** matching the Figma frames: `myntra-crm` (real, 8 images + copy ported from `axd-labs-site`), plus `cms-editor-revamp`, `web-template`, `rain-mazha`, `product-animations` — real copy/tags, **grey-box placeholders** for images until assets are added (drop files in `public/projects/<slug>/` and set `src` in `data/projects.ts`).
- Categories (filters): Motion Graphics · Brand Identity · Web Designs · Art Direction · Visual Design.
- About/contact content ported from `axd-labs-site/data`.

## 9. Bespoke case studies *(v0.5)*

- **A project may shadow the generic gallery.** `app/projects/cms-editor-revamp/page.tsx` is a static route that wins over `app/projects/[slug]`. The slug is listed in `BESPOKE` inside `[slug]/page.tsx` so `generateStaticParams` doesn't also generate it.
- **Why:** the CMS project's argument is a product document (service model → strategy → cost model → surfaces), not a screen gallery. `Project.blocks` is empty for it; `fullTitle` carries the long headline while `title` stays short enough for the list card.
- **Case kit** (`components/case/`): `CaseKit.tsx` (useInView, Section, SectionHead, `Chain`, Metric count-up, Card, Tag) · `Diagrams.tsx` (OrchestratorCompare, TokenEconomics, TierExplorer, BeforeAfter, UserGap, CaseProgress) · `FeatureBlock.tsx` · `ScreenFrame.tsx`.
- **`Chain` renders nodes and connectors as siblings, not nested pairs.** Nesting each node+connector in one `flex-1` wrapper made the rail distribute unevenly and pushed connectors beside nodes instead of between them. Node labels wrap rather than truncate.
- **`ScreenFrame`** wraps every screenshot in browser chrome with pointer-tilt and a **click-to-zoom lightbox** — these product screens are too dense to read inline.
- Motion stays dependency-free: one IntersectionObserver flips `.in`, the `/* Case-study layer */` block in `globals.css` does the rest. All of it collapses under `prefers-reduced-motion`.

- **2026-08-09 — v0.18** **EAT.JOBS**, a hidden arcade game at `/eat-jobs`, reached by tapping the home-page blob three times inside 700ms. Satire on "AI is eating our jobs": you are axd.blob, racing a red circle called **AI** to eat pellets labelled `job` out of a maze. Three rounds, each a fake rollout stage ("pilot program" → "company-wide adoption"), with AI faster each time. Win a round by taking more than half the jobs; lose and you get an automated-layoff memo with a "Appeal the decision" retry. Clear all three and you get a Certificate of Continued Human Employment. Every screen carries a link home so nobody gets stranded in the egg.
  - **Built dependency-free**, per the house rule: one `<canvas>` drawn at 20px-per-tile and upscaled with `image-rendering: pixelated`, on a fixed 1/120s timestep inside a hand-rolled rAF loop. Engine (`components/game/engine/`) is pure state with no React or DOM in it, which is what made it testable.
  - **Entities live on the grid, not in free space** — a tile plus `p`, the fraction travelled toward the next tile — and only turn at `p === 0`. The first attempt tracked float x/y and snapped to the nearest centre when within one step of it; that snaps an entity *back* to the centre it just left, so the blob vibrated on the spot and never moved. The tile+progress model can't drift into a wall no matter how frames land.
  - **The AI had to be made fallible.** A greedy BFS to the nearest pellet is unbeatable at *any* speed — a headless simulation of a perfect player still lost every round, 21 jobs to 102. Each level now carries a `confusion` chance (0.34 / 0.22 / 0.12) of taking a random turn instead of the shortest route, which is both winnable and truer to the joke. Re-simulated across three skill levels: L1 wins 80–100%, L2 44–92%, L3 8–64%, rounds 20–50s.
  - **Power-ups**: Coffee (+40% speed), Committee (AI stuck in a stakeholder alignment meeting), Recruiter (draws the route to the nearest job), Union (AI stops entirely). Touching AI doesn't kill you, it "restructures your role" — a 0.9s stun, since the joke is a race, not a chase.
  - **`aspect-ratio` bites when width is `auto`**: `.eatjobs-stage` pairs `aspect-ratio: 21/13` with a `min-height`, and on a phone the ratio resolved the *other* way, computing a 791px width from the 490px min-height and blowing the stage out of the cabinet. Fixed with an explicit `width: 100%` so the ratio only ever computes height.
  - `AxdBlob` gains a `secret` prop, set only on the home hero — `FooterBlob` wraps the blob in a `Link`, so an unconditional trigger there would fight its navigation. Tap 2 squashes harder (`blobCharge`) so the sequence is felt, not documented. The route is `noindex` and absent from the sitemap.

- **2026-08-06 - v0.16** Agent brain, mobile scroll fixes, background calm-down, and a content pass.
  - **`lib/agent.ts` is new: a real intent router, still with no LLM.** The home search bar now *answers* instead of only routing. Pipeline: normalise (punctuation, contractions, stopwords) → alias to a canonical concept → light stem → **fuzzy-alias** (Damerau-Levenshtein, tolerance scaled to word length) → score every intent by weighted phrase/keyword overlap → answer from a handcrafted script. Deterministic: the same question always produces the same answer, which is what makes it read as knowing rather than improvising.
    - **Typo correction happens at the alias stage, not at scoring time.** One correction then feeds every intent, instead of each intent needing to carry its own misspellings. This is what makes `protfolio`, `resmue`, `myntrra`, `brandng`, `animaton` and `hirng` all land.
    - **Transpositions cost 1, not 2** (optimal string alignment, not plain Levenshtein) because real typing swaps adjacent letters constantly: `resmue` is one swap from `resume`.
    - **`strong` keys** are proper nouns (a project's own name). They outscore shared discipline words, so `spider ai` is the Spider AI project, not the "how do you use AI" answer.
    - **Three reply tiers**: `routed` (a page exists → summarise + link), `answered` (true but page-less: rates, availability, process, tools), `deflected`. The deflection is never a dead end: it names the nearest thing it does know, and only falls back to a canned line when literally nothing scored. Variant choice is a hash of the query, so repeats are stable rather than randomly different.
  - **Loopholes found by testing, and closed**: `know` was aliased to the help intent and swallowed "do you know figma/react"; `won/win` sent "who won the world cup" to the awards answer; `loom` was a 4-letter strong key so "**look**ing to hire" fuzzy-matched Loomero; a bare "tell me about" phrase on the about intent stole "tell me about the cms project"; the thissite intent claimed the word "website" and stole "do you design websites"; and the awards answer linked to `/projects/tapse`, which **404s** because Tapse is an `externalUrl` project with no detail page. Recruiter vocabulary that was simply missing (`openings`, `vacancies`, `notice`, `joining`) was added.
  - **Verified against the running app**, not by inspection: 86 + 39 assertions on real typed input via Playwright (intent id is rendered as `data-intent`), a 231-query fuzz run (zero page errors, zero degenerate answers), and every internal action link fetched for a non-404.
  - **`components/search/AgentConsole.tsx`** replaces the bare `SearchBar` on the home page: same gradient bar, plus an "Ask" button, a ~480ms thinking state (the only thing standing in for latency, so it carries the illusion), and a capped 8-turn thread of question/answer pairs with action links and clickable follow-up chips. `SearchBar` stays for the nav pill, whose Enter still *navigates* — `lib/search.ts`'s `route()` now asks the agent where the answer lives first.
  - **Placeholder copy**: "Ask me anything…" is gone from both bars (it over-promises an LLM) → "Ask about the work, the experience, or hiring". The matching hero typewriter phrase changed too.
  - **Mobile horizontal scroll fixed, and the cause was two separate things.** The real layout bug: `FeatureBlock`'s grid items had no `min-w-0`, and an `auto` track is sized to its items' min-content contribution, which the monospace "How it's built" note made wider than a phone, so 5 of 8 CMS feature blocks pushed the document sideways. The rest was decorative bleed (portrait glow, screen-frame glow) escaping its box. `html`/`body` now use **`overflow-x: clip`, not `hidden`** — `hidden` on `body` alone does not stop `html` from growing, and `hidden` on `html` would make it a scroll container and break `position: sticky`. Verified: no horizontal scroll on 18 routes × 5 viewport widths (320-768).
  - **The fluid background is now route-aware** (`LOUD_ROUTES` in `FluidCursor.tsx`): full strength on home and about, and everywhere else canvas opacity 0.34, splat force ×0.42, radius ×0.55, dye ×0.41, and only every second pointer move injects at all. The simulation closure is set up once and never re-runs, so the route reaches it through a ref.
  - **Scroll progress rail on every project page.** `CaseProgress` (which lived in `Diagrams.tsx` and took an unused `sections` prop) is now `components/effects/ScrollProgress.tsx`, writing `transform` straight from the rAF callback rather than through React state, so a fast scroll doesn't queue a render per frame.
  - **Project detail footers all point home to `/projects`** rather than to the next project, and the "← All projects" text link under each one is gone (it was the same destination twice).
  - **`DISPLAY_ORDER` in `data/projects.ts`** is now the single source of sequence: `PROJECTS` is sorted by it, so it drives the "All" filter *and* anything else reading the array. The featured-first sort now only applies inside a category filter, where there's no curated order. **Blossom was not named in the requested sequence, so it falls to the end** rather than being dropped.

- **2026-08-04 — v0.8** Found and fixed a **site-wide** lightbox/fixed-positioning bug: `app/template.tsx`'s page-enter animation used `animation-fill-mode: both`, which keeps a *finished* animation "in effect" forever — and Chromium resolves its `filter`/`transform` end-state as `blur(0px)` / an identity matrix rather than a literal `none`, even though the keyframe says `none`.
